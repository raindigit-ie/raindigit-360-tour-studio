# Hybrid 512/2048 packaging benchmark — 2026-08-28

## Scope

- Same 21 original 11904×5952 panoramas from the Killarney Home source set.
- Before: legacy 512px deep-zoom pyramid.
- After: one 512px base WebP plus four 2048px detail WebPs per cube face and one 1024px JPEG fallback.
- DEV only. No active selector, production package, or production site was changed.

## Cold-build pipeline correction

The first hybrid benchmark changed the object layout but retained the expensive legacy pixel pipeline: 21 full-resolution ImageMagick derivatives, 126 separate FFmpeg invocations, repeated PNG intermediates and three Sharp decodes per cube face. A second implementation removes that duplicated work while retaining 4096px cube faces:

- neutral, unedited panoramas bypass the full-resolution ImageMagick re-encode;
- FFmpeg projects each face as an RGB24 pipe instead of writing and rereading a PNG;
- Sharp decodes the face once and creates four detail tiles, the base tile and fallback from the shared raw pixels;
- at most two faces are in flight, bounded by the 16 GB machine profile;
- Spline16 replaces Lanczos for projection: pre-encode comparison against Lanczos measured SSIM `0.996574` and PSNR `52.63 dB`; the 36 final lossy files of the sampled real scene measured PSNR `41.88 dB` and mean channel error `1.255`.

| Measurement | First hybrid implementation | Corrected pipeline | Change |
| --- | ---: | ---: | ---: |
| Cold build, same 21 panoramas | 485.62 s | 178.94 s | -63.2% (2.71× faster) |
| Base derivatives | 82.73 s | 10.02 s | -87.9% |
| Projection and media encoding | 397.21 s | 163.79 s | -58.8% |
| Warm build | 21.51 s | 14.24 s | -33.8% |
| One panorama changed | 39.78 s | 28.50 s | -28.4% |
| Peak RSS | 2,521,284,608 B | 2,304,950,272 B | -8.6% |

Compared with the exact legacy 512-tile cold build (`533.16 s`), the corrected pipeline is `2.98×` faster. Temperature remained bounded (average `72.58°C`, p95 `78.62°C`, maximum `80.33°C`) with no macOS thermal or performance warning. The local portable-release contract, hybrid raw/file byte-parity test, cube-projection parity and two-scene browser integration suite passed. This corrected package has not been uploaded or selected on DEV/PROD.

throughput and package-contract validity, not cross-platform visual parity.

## Runner saturation profile

The runner exposes 30 vCPU and approximately 110 GiB host RAM. A second sweep used
the same SHA-256-bound 21-scene input, a fresh empty cache for every cold run, Docker
network isolation, all CPUs (`0-29`) and a 100 GiB container memory ceiling. The
builder now selects concurrency from the resources actually visible inside its
container. Docker uses a bounded 12-task libuv queue and three libvips threads per
native operation. This is a throughput profile, not a requirement to allocate or
dirty otherwise-unused RAM.

| Profile | Cold wall | Internal total | Tiles phase | Peak CPU | Result |
| --- | ---: | ---: | ---: | ---: | --- |
| One scene, 6 faces, libuv 4, libvips 30 | 121.81 s | 120.59 s | 106.77 s | 2,115% | faster, oversubscribed native worker |
| One scene, 6 faces, libuv 8, libvips 4 | 111.98 s | 109.89 s | 94.79 s | 2,078% | improved native balance |
| One scene, 6 faces, libuv 12, libvips 3 | 110.23 s | 108.87 s | 93.90 s | 1,877% | best single-scene topology |
| Two scenes, 6 faces each, libuv 12, libvips 3 | 92.71 s | 92.06 s | 78.01 s | 2,718% | faster |
| **Three scenes, 6 faces each, libuv 12, libvips 3** | **83.07 s** | **82.18 s** | **67.67 s** | **2,620%** | **selected** |
| Exact commit `5d05a42`, selected profile confirmation | **71.69 s** | **69.91 s** | **54.76 s** | **2,703%** | **selected, repeat pass** |
| Four scenes, 6 faces each, libuv 12, libvips 3 | 101.06 s | 99.83 s | 85.42 s | noisy sample | rejected: contention |

The selected runner profile produced two independent cold results of
`71.69–83.07 s`: `2.15–2.50×` the native Mac M1 throughput (`178.94 s`) and
`1.62–1.88×` the previous runner concurrency-3 throughput (`134.52 s`). Its fully
cached repeat took `9.55 s` with 21/21 base and 21/21 multires cache hits. The
portable verifier passed, and all 756 generated media objects were byte-identical
to the earlier runner Docker reference. The exact-commit confirmation used an OCI
image labelled `5d05a42` after source-hash parity was checked between Mac and runner.

The Dockerfile was also reordered so volatile image metadata no longer invalidates
OS packages or application ownership layers. The first migration build took
`50.03 s`; after the new layer layout, an application-source update took
`2.79–3.87 s` and a revision-label-only rebuild took `2.00 s`. Docker runtime QA
passed on the runner, including non-root operation, read-only-root execution,
empty start, browser smoke, image import and persistent restart.
