# Hybrid 512/2048 packaging benchmark — 2026-08-28

## Scope

- Same 21 original 11904×5952 panoramas from the Killarney Home source set.
- Before: legacy 512px deep-zoom pyramid.
- After: one 512px base WebP plus four 2048px detail WebPs per cube face and one 1024px JPEG fallback.
- DEV only. No active selector, production package, or production site was changed.

## Cold network results

Each value is the median of three fresh Chromium mobile-touch contexts with browser cache disabled. Candidates were alternated within every repetition. `First ready frame` means the requested scene ID, runtime-ready state, and no more than 1% pure-black pixels. `Current-view detail settled` means the Pannellum renderer reported no pending tiles; it is measurement only and is not a reveal gate.

| Network profile | First ready frame before | First ready frame after | Detail settled before | Detail settled after |
| --- | ---: | ---: | ---: | ---: |
| Wi-Fi 50 Mbps / 20 ms | 2.466 s | 2.661 s | 3.106 s | 2.890 s |
| 4G 10 Mbps / 80 ms | 2.614 s | 3.007 s | 3.372 s | 3.727 s |
| Slow 4G 1.6 Mbps / 150 ms | 4.602 s | 5.218 s | 6.558 s | 11.840 s |

Initial transfer decreased from 943,199 B in 37 requests to 570,738 B in 18 requests (-39.5% bytes, -51.4% requests). Despite that reduction, the 2048px detail object creates a Slow-4G tail regression. This profile is therefore accepted as an infrastructure optimization candidate, not as the final user-loading optimum.

## Cold-build pipeline correction

The first hybrid benchmark changed the object layout but retained the expensive legacy pixel pipeline: 21 full-resolution ImageMagick derivatives, 126 separate FFmpeg invocations, repeated PNG intermediates and three Sharp decodes per cube face. A second implementation removes that duplicated work while retaining 4096px cube faces:

- neutral, unedited panoramas bypass the full-resolution ImageMagick re-encode;
- FFmpeg projects each face as an RGB24 pipe instead of writing and rereading a PNG;
- Sharp decodes the face once and creates four detail tiles, the base tile and fallback from the shared raw pixels;
- at most two faces are in flight, bounded by the 16 GB machine profile;
- Spline16 replaces Lanczos for projection: pre-encode comparison against Lanczos measured SSIM `0.996574` and PSNR `52.63 dB`; the 36 final lossy files of the sampled real scene measured PSNR `41.88 dB` and mean channel error `1.255`.

| Measurement | First hybrid implementation | Corrected pipeline | Change |
| --- | ---: | ---: | ---: |
| Cold build, same 21 panoramas | 485.62 s | 178.94 s | -63.2% (2.71× faster) |
| Base derivatives | 82.73 s | 10.02 s | -87.9% |
| Projection and media encoding | 397.21 s | 163.79 s | -58.8% |
| Warm build | 21.51 s | 14.24 s | -33.8% |
| One panorama changed | 39.78 s | 28.50 s | -28.4% |
| Peak RSS | 2,521,284,608 B | 2,304,950,272 B | -8.6% |

Compared with the exact legacy 512-tile cold build (`533.16 s`), the corrected pipeline is `2.98×` faster. Temperature remained bounded (average `72.58°C`, p95 `78.62°C`, maximum `80.33°C`) with no macOS thermal or performance warning. The local portable-release contract, hybrid raw/file byte-parity test, cube-projection parity and two-scene browser integration suite passed. This corrected package has not been uploaded or selected on DEV/PROD.
